# SWBLOG

KIMSUNGWOO의 인터랙티브 포트폴리오와 기록 공간.

## 실행과 빌드

Node.js 20 이상에서 별도 패키지 설치 없이 실행합니다.

```sh
npm run dev
npm run build
```

로컬 주소는 `http://127.0.0.1:4173`이며 정적 배포 파일은 `dist/`에 생성됩니다.
`npm run check`는 페이지의 인라인 스크립트와 공통 스크립트의 문법을 확인합니다.

## 화면 구조

- 사이트의 흰색은 두 가지로 통일했습니다: 페이지 #ffffff, 면(사이드바·이미지 자리·노트·패널 등) #f5f5f7. 예전의 따뜻한 종이색(#F7F1ED)과 그 계열 색, 따뜻한 회색 글자는 모두 중립색(#86868b, #6e6e73, #a1a1a6)으로 바꿨습니다. 새 페이지들은 `css/site.css`의 같은 토큰을 씁니다.
- 메뉴는 INFO / BLOG / GALLERY / PLAYGROUND입니다(예전 DEVELOP·DESIGN·LIFE는 뺐고, `cat_cod.html`은 파일만 남아 있음). 푸터의 Explore도 블로그·갤러리·플레이그라운드·소개·에디터로 바꿨습니다.
- 메뉴 옆 페이지들(info·blog·gallery·playground)은 `css/site.css`(색·서체·곡선·윗 메뉴)와 `js/siteData.js`(Supabase에서 글을 불러와 종류·해시태그·대표 이미지·읽는 시간·날짜·주소를 붙임)를 같이 씁니다. 글을 누르면 `index.html?post=번호`로 독자 화면이 열립니다. 윗 메뉴(`js/siteNav.js`)는 아래로 스크롤하면 위로 숨고 위로 스크롤하면 돌아오며, 돌아올 때는 밑에 깔린 면과 같은 색 바탕(#ffffff, `data-nav-surface="soft"`인 곳은 #f5f5f7, 다크는 #0a0a0b)을 깔아 글자나 사진이 메뉴 글자 사이로 지나가지 않습니다. 페이지 맨 위에서는 바탕 없이 떠 있습니다.
- `info.html`, `css/infoPage.css`, `js/infoPage.js`: 소개 페이지. 첫 화면 아래에 "Hello, I’m / Kim Sungwoo."를 여백에서 여백까지 크게(Circular Std) 두고, 소개 문장과 두 개의 짧은 노트, 사이트의 세 부분(Blog·Gallery·Playground, 실제 글 수와 한 줄 설명, 최신 글 한 줄), 해시태그 열 개(글 수), 연락처(#f5f5f7 면, "Say hello.")가 이어집니다. 글자는 줄마다 한 줄 높이 마스크 안에서 아래에서 올라오고(expo-out), 연락처 면은 아래에서 위로 닦여 나타납니다. 이메일은 `js/infoPage.js` 맨 위의 `EMAIL`에 적으면 메일 링크와 복사 버튼이 켜집니다(비어 있으면 "준비 중").
- `blog.html`, `gallery.html`, `css/sections.css`, `js/sections.js`: 블로그와 갤러리 목록. 큰 제목 아래 해시태그 거르기(그 페이지에 있는 태그만, 글 수와 함께, 회색 알약이 고른 태그로 미끄러짐, 주소의 `?tag=개발`로 공유 가능)가 있습니다. 블로그는 번호·제목·두 줄 요약·날짜·읽는 시간·태그와 작은 썸네일의 줄 목록이고, 갤러리는 사진의 실제 크기를 먼저 읽어서 큰 가로 사진만 화면 너비로, 나머지는 크고 작은 두 장을 엇갈려(한 쌍마다 좌우를 바꿔) 놓습니다. 줄과 사진은 화면에 들어올 때 마스크 안에서 올라오고 사진은 아래에서 위로 드러나며, 태그를 바꾸면 보이던 줄이 위로 빠져나가고 새 목록이 올라옵니다.
- `playground.html`, `css/playground.css`, `js/playground.js`: 다크 모드의 인터랙티브 글 목록. 모든 글이 1:1.2 사진 타일로 사방으로 끝없이 이어지는 판 위에 놓이고, 가운데 타일은 1.6배, 가장자리로 갈수록 0.42배까지 작아집니다(렌즈). 끌거나 튕기면 관성으로 흐르다 가장 가까운 글이 가운데에 멈추고, 그 글의 번호·종류·제목·태그·날짜·읽는 시간이 왼쪽 아래 캡션에 마스크로 올라옵니다. 휠은 한 칸씩, 방향키·Home·Enter도 됩니다. 클릭(터치는 가운데로 가져온 뒤 한 번 더)하면 독자 화면이 열립니다. 위의 칩으로 All/Blog/Gallery와 해시태그를 거르고(`?type=…&tag=…`), 오른쪽 아래에서 Field/List를 바꿉니다(움직임 줄이기 설정이면 List로 시작). 페이지가 스크롤되지 않으므로 윗 메뉴는 숨지 않습니다.
- 페이지 사이 이동(`css/pageTransition.css`, `js/pageTransition.js`, index·post·info·blog·gallery·playground 모두): 브라우저의 문서 간 view transition으로, 새 페이지가 아래에서 창처럼 올라오며 드러나고(창은 화면 높이만큼, 그 안의 내용은 24vh만 움직이는 마스크) 떠나는 페이지는 그 밑에서 18vh 위로 밀려납니다. 1.1초, 곡선은 패널이 접히고 펼쳐지는 것과 같은 cubic-bezier(.92,.15,.1,.93). 뒤로 가기에서는 반대 방향(위에서 아래)으로 움직입니다. info·blog·gallery 사이에서는 윗 메뉴가 제자리에 있고 그 아래 페이지만 바뀝니다. 새 페이지의 첫 등장 모션(글줄, 목록, 플레이그라운드의 물결)은 페이지가 반쯤 넘게 드러난 뒤에 시작합니다(`window.SwblogArrival`). 다른 페이지에서 `index.html?post=번호`로 오면 랜딩이 잠깐 보이지 않도록 첫 프레임부터 흰 판이 덮고 있다가 글의 로딩 종이(역시 흰색)가 걷힐 때 함께 사라집니다. 이 기능이 없는 브라우저(예: Firefox)는 그냥 다음 페이지를 엽니다(index의 메뉴 링크만 예전 덮개를 씀). 움직임 줄이기 설정에서는 끕니다.
- 메인 화면의 메뉴(화살표 버튼): 랜딩에서 열면 메뉴가 화면을 어둡게 하는 막 아래에 깔려 사이드바까지 함께 어두워지던 문제를 고쳤습니다(메뉴가 항상 막 위). 막도 옅게(10%, 흐림·어둡게 필터 없음) 바꿨습니다. 메뉴로 다른 페이지에 갔다가 뒤로 오면 메뉴는 닫혀 있습니다.
- `index.html`: Index Reel Landing → 글 목록과 우측 패널 이미지(panelField) → 패널형 독자 화면. 랜딩에서 스크롤하면 워드마크가 스크롤한 만큼 올라오고, 스크롤을 멈추면 다시 내려갑니다. 워드마크가 상자 줄에 닿으면 상자 줄이 아래에서부터 Y축으로 잘려서(clip-path) 상자의 아래 끝이 늘 워드마크 잉크 윗선보다 18px 위에 머뭅니다. 둘은 겹치지 않습니다. 랜딩의 상자를 누르면 바로 열리지 않고, 보이는 상자들이 무작위 순서로(55ms 간격) 아래에서 위로 잘려 사라진 뒤 상자의 로딩 배경색(#f5f5f7) 판이 아래에서 올라와 화면을 덮고, 그 아래에서 글이 열린 다음 판이 서서히 사라집니다. 화면 높이의 절반쯤을 이어서 굴려(터치는 30%) 워드마크가 화면 가운데에 닿으면 페이지가 놓입니다: 상자들이 아래에서 위로 닦여 사라지고, 워드마크는 그대로 이어서 글 목록 머리로 가며 글 목록이 올라오고, 페이지가 자리 잡을 즈음 오른쪽 패널이 화면 오른쪽 끝에 접혀 있다가 왼쪽으로 펼쳐집니다(0.9~1.8초, 곡선 cubic-bezier(.92,.15,.1,.93): 양끝에서 오래 머물고 가운데에서 빠르게 지나감). 패널은 창처럼 움직여서, 창은 오른쪽에서 들어오고 그 안의 내용은 같은 양만큼 반대로 움직이므로 이미지는 제 크기와 비율 그대로 서 있고 창의 왼쪽 끝만 이미지 위를 지나갑니다(마스크). 목록 맨 위에서 위로 당기면 오른쪽 패널이 먼저 오른쪽으로 접히고(0~0.8초), 그다음 글 목록이 내려가고 상자들이 위에서부터 다시 닦여 나타나며 랜딩에 돌아옵니다. 글 목록과 오른쪽 패널 사이에는 선이 없습니다. 박자들은 같은 곡선(4차 in-out)을 쓰고 앞 박자가 끝날 즈음 다음 박자로 넘어갑니다. 모두 `transform`만 쓰는 브라우저 애니메이션(WAAPI)이라 스크립트가 프레임마다 값을 넣지 않습니다. 닦임은 레일 상자를 위로, 그 안의 레일을 같은 양만큼 아래로 움직여 만듭니다. 워드마크는 섞이지 않는 평범한 잉크색이고, 크기와 위치를 스크립트가 맞춰 글자의 잉크(박스가 아니라)가 랜딩에서는 좌우 여백(상자 줄의 양끝)에, 글 목록에서는 사진의 양끝에 정확히 닿습니다. 로고의 잉크와 메뉴 화살표의 끝도 랜딩에서 같은 양끝에 맞춥니다.
- 오프닝: 상자 줄의 가운데 상자부터 바깥쪽으로 차례로, 상자가 아래에서 위로 닦이며 나타나고 사진은 살짝 확대된 상태에서 제자리로 가라앉습니다. 그동안 워드마크·로고·메뉴 화살표는 숨겨져 있다가, 상자들이 거의 다 나타나면 워드마크가 제 기준선에서 솟아오릅니다.
- 글은 두 종류입니다: **블로그**(글 위주, 지금의 독자 화면)와 **갤러리**(포트폴리오처럼 큰 이미지 위주). 종류는 에디터에서 고르고, 본문에 보이지 않는 주석 `<!--swblog:type gallery-->` / `<!--swblog:type blog-->`로 저장되어 DB 구조를 바꿀 필요가 없습니다(`js/postType.js`). 이 주석이 없는 예전 글은 내용으로 정합니다: 이미지가 4장 이상이고 글이 거의 없거나(이미지당 40자 이하), DESIGN 카테고리에 이미지가 5장 이상이면 갤러리, 나머지는 블로그입니다(지금 글 중 갤러리 7개, 블로그 9개). DB의 글은 고치지 않았고, 에디터에서 다시 저장하면 그때 종류가 주석으로 기록됩니다.
- 예전의 카테고리 세 개(CODING / DESIGN / LIFE)는 없앴습니다. 큰 분류는 위의 두 종류(블로그 / 갤러리)이고, 세부 분류는 해시태그 10개 중 최대 3개입니다: #디자인 #개발 #인터랙션 #브랜딩 #타이포그래피 #사진 #프로젝트 #회고 #일상 #실험 (`js/postTags.js`). 해시태그는 posts 테이블의 기존 `category` 칸에 "디자인,개발"처럼 글자로 저장되어 DB 구조를 바꿀 필요가 없고, 예전 값은 읽을 때 바뀝니다(CODING·TECH → #개발, DESIGN → #디자인, LIFE → #일상). 글 머리의 오른쪽 위에는 BLOG / GALLERY, 날짜·읽는 시간 뒤에 해시태그가 붙고, 사이드바·오른쪽 패널·갤러리 정보·다음 글 추천도 해시태그를 씁니다(다음 글은 같은 종류에서 해시태그가 겹치는 글을 먼저 고름). 목록의 작은 마크는 종류를 나타냅니다(블로그 별, 갤러리 꽃).
- 글 목록은 너비가 다른 두 열입니다(약 3 : 2). 갤러리 글은 넓은 왼쪽 열에, 블로그 글은 좁은 오른쪽 열에 각각 최신순으로 쌓이고(스크립트가 각 글의 자리와 폭 --x, --y, --w와 목록 높이 --list-h를 정함), 사진은 모두 가로 1 : 세로 1.2입니다. 사진 아래에는 제목(21–30px, 보통 굵기 400, 최대 두 줄)과 오른쪽 끝의 번호만 놓입니다(같은 기준선). 격자는 글을 두 개씩 한 줄로 놓으므로, 스크립트가 좁은 열의 글을 바로 앞 글 아래로 끌어올리고(--stack, 상대 위치라 다른 요소를 다시 배치하지 않음) 좁은 열이 넓은 열보다 짧은 만큼(--lag) 스크롤에 뒤처지게 합니다. 뒤처짐은 목록이 화면을 지나가는 동안(--lag-start → --lag-end)에만 일어나므로, 두 열은 함께 들어와 마지막 줄이 화면 아래에 닿을 때 나란히 끝나고, 좁은 열이 더 느리게 스크롤됩니다. 움직임은 CSS 스크롤 타임라인(데스크톱은 목록 패널, 폰은 페이지)이 맡아서 스크롤과 같은 프레임에 움직이고 스크립트는 매 프레임 일하지 않습니다(지원하지 않는 브라우저에서는 뒤처짐 없이 쌓이기만 합니다). 폰에서도 같은 두 열입니다. 호버는 가리킨 글에만 일어납니다: 사진이 틀 안에서 4.5% 커지고(expo-out, 틀 크기는 그대로). 제목이 위로 말려 올라가며 두 번째 벌이 아래에서 올라와 글자마다 카테고리 색으로 물결칩니다. 주변 글은 움직이지 않고 어느 것도 흐려지지 않습니다. 메인화면에서 넘어올 때 보이는 글들은 올라오는 페이지와 함께 그대로 도착하고, 스크롤해서 새로 들어오는 글만 사진이 위에서 아래로 닦이며 나타납니다. 이때 사진을 먼저 디코딩한 뒤 애니메이션을 시작해서 중간에 멈칫하지 않습니다. 두 벌의 제목은 같은 전환(750ms expo-out)을 같은 순간에 시작하고 정확히 한 칸 떨어져 있어서, 포인터가 어떻게 드나들어도 겹치거나 벌어지지 않습니다. 글이 나타날 때의 움직임은 제목 두 벌이 아니라 그 둘을 - `js/galleryReader.js`, `css/gallery.css`: 갤러리 글의 독자 화면. 본문을 순서대로 읽어 다시 짭니다: 첫 이미지 앞의 글은 프로젝트 시트(왼쪽에 Category·Date·Images, 오른쪽에 도입 글), 이미지는 큰 판(한 장은 화면 너비 가득, 이어지는 이미지는 한 장 → 두 장 나란히 → 한 장… 순서, 세로로 긴 이미지는 너비 2/3로 오른쪽), 이미지 사이의 글은 오른쪽에 짧은 노트로 놓입니다. 판은 화면에 들어올 때 아래에서 위로 드러나며 사진이 살짝 확대된 상태에서 가라앉고(expo-out), 스크롤에 따라 틀 안에서 조금 흐릅니다(CSS view timeline이라 스크립트가 스크롤을 기다리지 않음). 화면 아래 왼쪽의 카운터(03 / 12)가 지금 보는 이미지를 반전 글자로 보여 주고, 이미지를 누르면 크게 열립니다. 갤러리 글에서는 목차와 머리 이미지는 숨깁니다. 에디터의 미리보기(preview.html)도 같은 방식으로 보여 줍니다.
- `js/panelField.js`: 글 목록 오른쪽 패널. 아스키 아트 대신 각 글의 "우측 패널 이미지"를 패널 가득(object-fit: cover) 보여 줍니다. 패널 이미지가 없는 글은 첫 이미지를 씁니다. 처음에는 최신 글의 이미지가 서 있고, 글을 가리키면 그 글의 이미지로 바뀌며, 목록에서 벗어나도 마지막 이미지가 남습니다. 새 이미지는 아래에서 위로 드러나고(창은 올라오고 그 안의 이미지는 같은 만큼 내려가 제자리에 선 채로 덮이는 방식, 1.15초 expo-out) 살짝 확대된 상태에서 제자리로 가라앉으며(1.7초), 아래 이미지는 조금 밀려 올라갑니다. 이미지 가운데 높이에는 글자 세 개가 가로로 놓입니다: 왼쪽에 카테고리, 가운데보다 조금 왼쪽에 날짜, 오른쪽에 읽는 시간(본문 글자 수 ÷ 500, 독자 화면과 같은 계산). 배경 없이 가는(300) 흰 글자를 difference로 섞어 이미지 위에서 반전되므로 밝은 이미지에도 어두운 이미지에도 보입니다. 각 글자(아래 캡션도)는 딱 한 줄 높이의 마스크 안에 있어, 바뀔 때 앞 글자는 마스크 밖으로 올라가며 완전히 가려집니다. 패널 아래의 종이 띠 캡션에는 번호와 제목이 놓입니다. 글이 바뀌면 라벨 세 개와 캡션의 글자가 각자 마스크 안에서 차례로 밀려 올라갑니다(앞 글자는 위로 빠져나감). 날짜와 읽는 시간은 글 목록의 각 행에 data-date, data-read로 실려 있습니다. 패널 이미지는 에디터의 "우측 패널 이미지" 버튼으로 올리며, 본문에는 보이지 않는 주석 `<!--swblog:panel URL-->`으로 저장되어 DB 구조를 바꿀 필요가 없습니다(세로로 긴 이미지 권장).
- `js/publication2026.js`, `css/publication2026.css`: 공통 모션, 관성 있는 커서 이미지, 퍼센트 진입 장면, 표지·챕터·읽기 완료·다음 글과 모바일 목차를 연결합니다. 글 로딩 화면은 종이가 올라오며 아래 화면이 150px 끌려 내려가고 살짝 작아지며, 가운데에 헤더 로고와 같은 크기의 연한 로고가 떠오릅니다. 글이 불러와지는 동안 로고가 바닥부터 몇 걸음에 걸쳐 차오르는데, 채우는 것은 카테고리 색(파랑 → 분홍 → 노랑) 띠가 글자 안에서 계속 위로 흘러 올라가는 무지개입니다. 다 차면 종이가 빠르게 걷히며 천천히 멈추고 글이 220px 아래에서 따라 올라옵니다. 이미 한 번 불러온 글로 갈 때는 같은 종이가 아래에서 올라와 멈추지 않고 위로 지나가며, 그 아래에서 글이 바뀌어 올라옵니다. 첫 이미지에 있던 픽셀화 효과는 이미지가 깨진 것처럼 보여 없앴습니다. 글을 닫으면 종이 한 장이 왼쪽에서 글을 덮고(글은 오른쪽으로 180px 밀리며 작아지고), 그 아래에서 목록이 다시 짜인 뒤(읽던 글이 가운데 오도록 스크롤까지 맞춤) 오른쪽으로 걷혀서(목록은 200px 뒤에서 따라 들어옴), 중간에 깜빡이거나 갑자기 생기는 요소가 보이지 않습니다.

`node tools/test-panel-field.mjs`는 패널 이미지 주석 읽기, 패널 이미지 우선순위, 마지막으로 가리킨 글이 이기는 경합과 목록을 벗어날 때의 유지를 검사합니다. `npm run build`로 배포용 `dist/`를 갱신합니다.

Landing의 `.page`와 `.masthead`는 카드 위의 투명한 전경입니다. 이 배경을 불투명하게 만들면 아래 카드가 가려집니다. 글 목록은 `makeWaveText`, `text-wave-anim`, `rotate_cat`, `cat_b.png`/`cat_y.png`/`cat_r.png`를 유지하며, 후순위 스타일에서 이를 끄거나 작은 도형으로 대체하지 않습니다. 모션 감소 설정에서는 애니메이션만 정지하고 콘텐츠와 탐색은 유지합니다.

모션 메모(gilhuybrecht.com 참고): 글 목록의 사진은 목록이 움직이는 속도에 따라 프레임 안에서 살짝 부풀고 뒤처졌다가 멈추면 제자리로 돌아옵니다(보이는 사진에만, 개별 `scale`·`translate` 속성으로 써서 호버 확대와 등장 애니메이션의 `transform`과 겹치지 않음). 호버의 제목 굴림·사진 확대와 등장 애니메이션은 expo-out(`cubic-bezier(.19,1,.22,1)`)을 쓰고, 데스크톱 스크롤 스프링은 Lenis(lerp .15)에 가깝게 조금 더 부드럽게(ω 12) 미끄러집니다.

성능 메모: 루트(`html`)의 CSS 변수와, 많은 자식을 둔 요소의 상속 속성(`pointer-events`, `visibility`)은 움직이는 동안 바꾸지 않습니다. 둘 다 하위 요소 전체의 스타일을 다시 계산하게 해서 수십 ms씩 멈춥니다. 움직임에 쓰는 값은 해당 요소의 `transform`/`opacity`에 직접 씁니다.

본문의 일반 소제목은 한 열의 읽기 흐름으로 구성됩니다. 에디터에서 직접 삽입한 2열 섹션은 별도로 유지하며, 인용·번호 목록·이미지·코드 블록은 공통 규칙을 따릅니다. 제목과 똑같은 본문 첫 제목은 독자 화면에서 중복 표시하지 않습니다. 미리보기는 원문을 복제해 표시하며 글을 발행하지 않습니다.

## 운영

기존 Supabase 프로젝트와 공개 클라이언트 설정을 유지합니다. 새 저장소 생성은 데이터베이스 이전이나 실제 사이트 배포를 수행하지 않습니다. 인증된 저장·발행은 해당 프로젝트의 권한과 RLS 정책을 따릅니다. 외부 글 데이터, 폰트와 CDN 스크립트에는 인터넷 연결이 필요합니다.
